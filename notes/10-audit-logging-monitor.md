# 10｜审计日志、后台线程与监控终端

> 对应源码：`cyberclaw/core/logger.py`、`entry/monitor.py`  
> 辅助源码：`cyberclaw/core/agent.py`、`entry/cli.py`

## 一、本课核心内容

### 1. 整体链路

```text
agent_node
→ audit_logger.log_event
→ queue.Queue
→ daemon writer thread
→ logs/<thread_id>.jsonl
→ monitor tail
→ Rich 渲染
```

### 2. 单例 Logger

`__new__()` 使用类锁保证进程内只创建一个 Logger 和一个 writer thread。

第一次传入的 `log_dir` 生效，后续构造仍返回旧实例，因此不同目录或测试实例不易隔离。

### 3. 导入副作用

模块底部立即创建 `audit_logger`。导入时就会创建相对 `logs` 目录、队列、后台线程和 `atexit` 回调。

CLI 会先切换到项目根目录，所以正式运行通常写到根目录 logs；其他入口直接导入时，目录取决于当时 cwd。

### 4. 异步式日志写入

Agent 线程只构造事件并入队，文件序列化和写入由后台线程处理。

这里的“异步”是线程解耦，不是 `asyncio` 协程。跨线程通信使用线程安全的 `queue.Queue`。

### 5. JSONL

一行一个 JSON 事件，适合追加、tail 和流式处理。

writer 按清洗后的 `thread_id` 分文件，每次事件都以追加模式重新打开和关闭文件。

### 6. 事件种类

当前 Agent 写入：

```text
llm_input  → 消息条数
tool_call  → 工具名和完整参数
tool_result→ 工具结果前 200 字符
ai_message → 最终回答全文
```

缺少 run ID、模型、Token、延迟、异常、状态持久化和用户输入等信息。

### 7. 正常关闭

`atexit` 调用 `shutdown()`，把 `None` 哨兵放到队列末尾并 `join()`。writer 处理完前序事件后退出。

强制终止不能保证刷新；`shutdown()` 重复调用还可能因 writer 已结束而永久等待。

### 8. Monitor 行为

Monitor 固定监听：

```text
logs/local_geek_master.jsonl
```

打开后 `seek` 到文件末尾，所以只显示 Monitor 启动后的新事件。

它渲染 `llm_input`、`tool_call`、`tool_result` 和 `system_action`；没有渲染实际写入的 `ai_message`，而 `system_action` 当前又没有生产者。

### 9. 主要边界

- 日志队列无上限，慢磁盘时可能增长内存；
- 写入失败只打印并丢失事件；
- 没有轮转、保留、压缩和磁盘配额；
- 没有跨进程写锁；
- Monitor 不能选择 thread 或查看历史；
- 日志轮转后 Monitor 不会自动重新打开；
- `except: pass` 会静默隐藏坏行和代码错误；
- 工具参数与回答没有脱敏；
- Rich 直接渲染不可信文本，可能受 markup 影响。

## 二、自测题与参考答案

### 1. 为什么 Logger 采用单例？

**参考答案：**

为了在同一进程中共享一个队列和一个 writer thread，避免每次导入或构造都创建新的后台写入器。类锁保证并发首次构造时只初始化一次。

### 2. 单例的代价是什么？

**参考答案：**

第一次 `log_dir` 永久生效，后续无法自然创建独立配置实例；全局状态和后台线程使测试隔离、重置和生命周期管理更困难。

### 3. 为什么使用 `queue.Queue`？

**参考答案：**

生产者在 Agent 执行线程，消费者是独立 writer thread，需要线程安全队列。`asyncio.Queue` 主要用于同一事件循环中的协程通信，不适合直接作为线程间队列。

### 4. 无界队列有什么优缺点？

**参考答案：**

优点是日志入队通常不会因容量满而阻塞 Agent；缺点是写入速度跟不上时没有背压，积压会持续占用内存。

### 5. daemon thread 有什么含义？

**参考答案：**

守护线程不会阻止进程退出。正常退出可借助 `atexit` 刷新，但强制终止时队列中的日志可能丢失。

### 6. JSONL 和普通 JSON 数组有什么区别？

**参考答案：**

JSONL 每行是一个完整 JSON 对象，可以持续追加并逐行 tail；JSON 数组通常要维护整体括号和逗号，不便于不停追加。

### 7. thread ID 怎样变成日志文件名？

**参考答案：**

只保留字母数字、连字符和下划线，空结果改为 `default`，然后使用 `<safe_id>.jsonl`。这种清洗降低路径穿越风险，但不同原始 ID 可能发生碰撞。

### 8. 写日志失败会影响 Agent 吗？

**参考答案：**

通常不会直接中断 Agent。writer 捕获异常、打印错误并对队列项调用 `task_done()`，但该事件会丢失，也没有重试和告警。

### 9. `atexit` 怎样帮助刷新日志？

**参考答案：**

正常解释器退出时调用 `shutdown()`，把 `None` 放到 FIFO 队列末尾。writer 先处理完已有日志，再消费哨兵并退出，`join()` 等待全部标记完成。

### 10. 为什么 `shutdown()` 不能安全调用两次？

**参考答案：**

第一次调用后 writer 已退出。第二次再放入 `None`，没有消费者调用 `task_done()`，于是 `queue.join()` 可能永久等待。

### 11. `tool_result` 什么时候记录？

**参考答案：**

工具节点执行完并回到下一次 `agent_node()` 时，代码从当前消息末尾找到连续 ToolMessage，再记录每条结果的前 200 字符。

### 12. Monitor 为什么看不到启动前的旧事件？

**参考答案：**

`tail_f()` 打开文件后执行 `seek(0, 2)` 移到文件末尾，随后只读取新追加行。

### 13. 为什么 Monitor 看不到 `ai_message`？

**参考答案：**

虽然主题中定义了样式，`render_event()` 却没有 `event == "ai_message"` 的处理分支。

### 14. `system_action` 为什么通常也看不到？

**参考答案：**

Monitor 有渲染分支，但当前核心代码没有调用 Logger 生产这种事件。

### 15. 当前日志为什么不是完整审计系统？

**参考答案：**

它缺少一次请求的完整关联 ID、主体身份、模型版本、延迟、Token、异常和持久化结果；写入还可能丢失，没有防篡改、保留策略和完整性保证。

### 16. 日志为什么会造成隐私风险？

**参考答案：**

工具参数和 AI 回答按原值写入，可能含文件内容、命令、画像和用户数据。`.gitignore` 只避免 Git 提交，不提供加密、访问控制、脱敏和自动删除。

## 三、面试追问与回答思路

### 1. 怎样设计可关联的一次 Agent trace？

**回答思路：**

为每个用户请求生成 run ID，为每个模型和工具调用生成 span ID，记录 parent-child、开始结束时间、状态、模型、Token、重试和错误；thread ID 只负责会话，不替代 run ID。

### 2. 怎样改进 Logger 生命周期？

**回答思路：**

避免导入即启动，使用显式 start/close 或上下文管理器；用状态锁保证 close 幂等；关闭后拒绝新事件；设置有界队列和明确的丢弃/阻塞策略，并等待后台线程确认结束。

### 3. 怎样处理敏感日志？

**回答思路：**

先建立字段分类与最小化原则；对密钥、文件内容、画像和命令参数做结构化脱敏；限制访问权限，配置加密、保留和删除策略；高风险字段默认不记录，必要时由用户显式开启。

### 4. 怎样支持日志轮转？

**回答思路：**

按大小或日期轮转，限制保留数量并压缩旧文件；writer 与 tailer通过明确协议感知新文件；多进程环境使用集中日志服务或可靠 handler，而不是共享普通 append 文件。

### 5. 为什么可观测性不能只靠日志？

**回答思路：**

还需要 metrics 衡量吞吐、延迟、错误率和队列深度，traces 关联一次请求的各阶段，logs 提供离散细节。三者结合才能定位系统性问题。

### 6. 简历中怎样描述日志改造？

**回答思路：**

可以写“构建带 run/span 关联、敏感字段脱敏、轮转和背压的 Agent 事件管道，并接入指标与 trace”。应提供故障场景和性能数据，不能把当前简单 JSONL tail 描述成完整生产级监控平台。
