# 11｜测试、示例、文档与实现一致性

> 对应范围：`tests/`、`examples/`、`docs/`  
> 辅助文件：`README.md`、`CHANGELOG.md`、`LICENSE`

## 一、本课核心内容

### 1. 三方对照原则

```text
代码 → 实际做了什么
测试 → 哪些输入输出被自动验证
文档 → 对外声称什么
```

测试名、注释、README 和性能表都不是事实本身，必须回到执行路径和断言。

### 2. 当前测试基线

此前 Windows 环境结果：

```text
53 项被 pytest 收集
52 项通过
1 项因打开的 NamedTemporaryFile 无法删除而失败
```

这表示当前断言的结果，不代表全功能、全平台、安全性和性能都已证明。

### 3. 测试文件结论

| 文件 | 主要证明 | 主要缺口 |
|---|---|---|
| `test_agent.py` | Agent 可以被组装和编译 | 从未执行图和工具循环 |
| `test_builtins.py` | 部分工具 happy path 和任务 CRUD | 时间断言弱、月末不稳定、安全边界少 |
| `test_heartbeat.py` | 大量测试夹具可读写 | 几乎没有真正执行 pacemaker |
| `test_context_advanced.py` | 按 Human 回合裁剪的纯函数行为 | 没测摘要、RemoveMessage 与 checkpoint |
| `test_config_and_skill_loader.py` | 配置和 loader 可导入，空目录返回空 | 没测配置优先级和真实 Skill 生命周期 |
| `test_sandbox_tools.py` | 普通文件操作与几个黑名单样例 | 未证明路径、链接和 Shell 隔离安全 |
| `test_lazy_loader.py` | 临时 Skill 扫描、help、重扫和缓存入口 | 计时易抖动，没测运行中 Agent 热更新 |
| `test_two_phase_skills.py` | 提供真实模型比较脚本 | 不被 pytest 收集，随机、昂贵、不可稳定复现 |

### 4. Heartbeat 测试的关键问题

很多用例只是把自己构造的 JSON 写入再读出；缺失文件和空文件测试内部是 `pass`；重复逻辑在测试中重新手写；队列测试是 `assertTrue(True)`。

因此测试文件名叫 Heartbeat，不等于到期扫描、入队和续期行为已被覆盖。

### 5. 相对可靠的 context 测试

它直接调用纯函数并检查 kept/discarded 的类型和数量，能证明回合分组的具体行为。

仍没有覆盖：

- 恰好等于 trigger；
- 异常消息序列；
- 摘要模型；
- reducer 删除；
- SQLite 恢复。

### 6. 两阶段评测的真实定位

`test_two_phase_skills.py` 只有 `run_experiment()`，不是 pytest 测试。

它使用真实模型、随机工具顺序和 20 个场景；runner 也没有强制 help 状态。README 引用的 `run_tests()` 和报告文件都不存在，因此宣传百分比不可追溯。

### 7. 示例边界

`basic_usage.py` 展示同步节点流，但：

- 模型硬编码；
- 没有 checkpointer；
- 不含正式异步运行时；
- 没把 AI/Tool 消息并回下一轮 state。

`benchmark_lazy_loading.py` 测了扫描和 help 时间，但预加载耗时、内存、百分比和“无限扩展”是打印的假设，不是完整测量。

### 8. 文档主要偏差

```text
Heartbeat 独立进程、每秒扫描 → 实际主进程协程、10 秒
摘要每 20 回合              → 实际 40/10
原生 MCP 集成               → 核心没有 MCP 实现
零信任 help→run             → 没有程序级强制
Skill 零停机热更新          → 运行中 Agent 不会重绑
全部测试通过                 → Windows 基线有一个夹具失败
PowerShell + CMD 完整支持    → 没有双 Shell 适配层
```

此外还存在：

- README 的 `run_tests()` 不存在；
- `test_context.py` 文件名错误；
- `tests/logs/test_two_phase_skills.md` 不存在；
- docs 链接的两篇设计文档不存在；
- 结构图把 `.env` 错画到 office；
- Monitor 未渲染 `ai_message`；
- CHANGELOG 把未验证数字写成事实。

### 9. 文档资产与 License

README 引用的本地 PNG 均存在。

项目采用 MIT License，允许 fork、修改和发布，但必须保留原版权与许可。简历中应明确“基于开源 CyberClaw 二次开发”，区分原有能力与自己的贡献。

### 10. 工程证据层级

应区分：

```text
未实现
已实现未测试
部分测试
自动验证
人工验证
可复现 benchmark
```

不能因为文档出现一个特性名称，就把它当成已验证功能。

## 二、自测题与参考答案

### 1. 为什么 52 项测试通过不等于项目正确率 98%？

**参考答案：**

测试项不是均匀覆盖的功能样本，很多断言很弱或重复验证夹具；关键主链可能完全未执行。通过率只描述已收集断言的结果，不能直接映射为产品正确率。

### 2. `test_agent.py` 证明了什么？

**参考答案：**

证明在 Mock 模型和工具条件下，Agent 图可以构造和编译，也能接受自定义工具和 checkpointer。它没有调用图，所以未证明工具循环、摘要或状态恢复。

### 3. 为什么 Mock 应 patch 使用方名称？

**参考答案：**

如果模块通过 `from x import y` 保存了本地引用，之后 patch `x.y` 不会自动改变已导入模块的本地 `y`。应 patch `cyberclaw.core.agent.get_provider` 这类实际查找位置。

### 4. 时间工具测试为什么可能错误通过？

**参考答案：**

生产输出和测试替换使用不同冒号，解析失败后测试进入 fallback，只断言字符串非空，因此没有真正验证日期格式。

### 5. Heartbeat 测试最大的缺陷是什么？

**参考答案：**

大多数用例没有执行 `pacemaker_loop()` 或可提取的单次处理逻辑，只验证测试自己写入的 JSON；队列交互甚至是恒真的占位断言。

### 6. Windows 临时文件失败说明什么？

**参考答案：**

说明测试在文件句柄仍打开时删除文件，不符合 Windows 文件共享语义。应先关闭句柄或使用更合适的临时目录/路径夹具。这不直接证明 Heartbeat 功能错误。

### 7. 为什么 `test_context_advanced.py` 的证据更强？

**参考答案：**

它直接调用目标纯函数，以具体消息序列检查返回类型和数量，断言与生产逻辑直接相关，而不是只检查导入成功或夹具自身内容。

### 8. sandbox 测试为什么不能证明“沙盒安全”？

**参考答案：**

它只验证一个 `../../` 和五个黑名单字符串，没有覆盖路径前缀碰撞、链接、Junction、编码转义、脚本间接执行、网络和资源限制等攻击面。

### 9. 为什么 `test_lazy_loader` 的计时断言可能不稳定？

**参考答案：**

单次短时间测量会受到时钟精度、OS 文件缓存、调度和后台负载影响。缓存命中不保证每次观测值严格小于第一次。

### 10. 为什么 `test_two_phase_skills.py` 不会进入普通 pytest 结果？

**参考答案：**

它没有 `test_` 开头的测试入口，主要函数叫 `run_experiment()`，只在脚本作为主程序运行时调用。

### 11. 两阶段评测为何难以复现？

**参考答案：**

依赖真实模型和网络，工具顺序随机且未固定 seed，没有锁定模型版本与完整采样条件，只有有限场景和单次运行，也没有提交原始报告。

### 12. benchmark 的哪些结论没有被脚本测量？

**参考答案：**

没有真实运行预加载对照，没有测 RSS/heap 内存，也没有验证无限 Skill、热更新和模型工具选择。相关 2000ms、250KB、80% 等是硬编码展示值。

### 13. README 关于 Heartbeat 的三个错误是什么？

**参考答案：**

它不是独立后台进程，而是主程序中的协程 Task；扫描间隔是主入口传入的 10 秒，不是每秒；仓库也没有在主程序关闭后自动运行 Heartbeat 的独立服务入口。

### 14. README 关于上下文压缩哪里不一致？

**参考答案：**

README 写每 20 轮触发并保留 10 轮，主 Agent 实际显式传入 `trigger_turns=40`、`keep_turns=10`。

### 15. 为什么不能说项目已原生集成 MCP？

**参考答案：**

核心没有 MCP 客户端、服务端、transport、session、工具发现或协议调用。外部 Skill 通过 Shell 调用 MCP CLI 只能算间接扩展。

### 16. MIT License 对 fork 有什么要求？

**参考答案：**

允许使用和修改，但在软件副本或实质部分中必须保留原版权声明与许可文本。还应在简历和项目说明中诚实区分原作者与自己的贡献。

### 17. README 本地图片是否缺失？

**参考答案：**

当前引用的九个本地 PNG 都能在 `docs/` 找到；主要失效项是某些 Markdown、测试报告、函数名和结构描述，不是这些图片。

### 18. 怎样判断一条性能数字能否写进简历？

**参考答案：**

要有明确对照组、机器与依赖环境、数据规模、冷热缓存条件、重复次数、统计方法、原始结果和可运行脚本。缺少这些就只能描述机制，不能宣称确定百分比。

## 三、面试追问与回答思路

### 1. 你会优先补哪一个测试？

**回答思路：**

先用可脚本化 fake chat model 做 Agent 工具循环集成测试，因为它覆盖最核心状态图协议；随后提取 Heartbeat 单周期函数，验证到期入队和任务续期。优先级根据业务风险而不是文件覆盖率决定。

### 2. 如何测试一个安全边界？

**回答思路：**

先定义不变量，例如“任何解析后的真实路径必须位于 office”。再围绕路径、链接、平台、大小写、竞态和命令组合生成攻击用例，并在低权限隔离环境验证系统能力，而不是只维护字符串黑名单样例。

### 3. 如何让真实模型 eval 可复现？

**回答思路：**

版本化数据集和评分器，固定模型快照、temperature 和 seed（服务支持时），记录提示与工具顺序，多次重复并报告方差/置信区间，保存原始轨迹、失败样例、成本和运行元数据。

### 4. 怎样防止文档再次漂移？

**回答思路：**

在 CI 中执行命令示例、检查文件和链接存在性；从代码常量自动生成阈值或配置表；每个能力关联测试；合并请求模板要求同步变更文档；减少中英文全文复制。

### 5. 如何向面试官解释你 fork 了开源项目？

**回答思路：**

先说明原项目和 License，再解释自己完成的源码审计、发现的具体缺口、选定的改造主线、设计决策、提交和可量化结果。开源二次开发的价值在于理解和工程贡献，不在于隐藏来源。

### 6. 怎样描述当前项目最准确？

**回答思路：**

它是一个可运行的本地 LangGraph Agent 学习原型，包含工具、记忆、定时任务、文档驱动 Skill 和 JSONL 日志；部分产品级声明尚缺强制机制、完整测试和可复现数据。
